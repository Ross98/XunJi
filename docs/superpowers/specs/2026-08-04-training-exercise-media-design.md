# 训练详情动作示意图 — 设计

## 1. 背景与目标

XunJi 当前训练详情只显示动作名称和组数。接入 `Ross98/exercises-dataset`，为训练详情中能匹配的动作显示本地 GIF 示意图。

目标：

- 本地保存上游全量动作数据和媒体资源。
- 在训练详情页动作旁显示 180×180 GIF。
- 保留现有训练文字、组数、容量和错误降级行为。
- 未匹配动作不显示错误图片，也不阻断训练详情。
- 保留上游许可证、媒体署名和来源说明。

项目当前按个人本地使用接入。若未来公开部署或向他人分发，必须重新核对 Gym visual 媒体条款并按要求取得许可。

## 2. 范围

### 包含

- `data/exercises.json` 和 `data/exercises.schema.json`。
- 全部 1,324 张 180×180 缩略图。
- 全部 1,324 个 180×180 动画 GIF。
- 上游 `LICENSE` 和 `NOTICE.md`。
- 训练详情页动作媒体展示。
- 中文动作名与数据集英文动作名的明确别名匹配。
- 媒体索引、匹配和资源完整性测试。

### 不包含

- 上游 `index.html`、`setup.html` 等独立浏览器工具。
- 新增独立动作图库页面。
- 训练记录数据结构或训记 API 协议修改。
- 模糊匹配或基于猜测的动作图片推荐。
- 运行时从 GitHub 下载资源。

## 3. 本地资源布局

资源放在现有 FastAPI 静态目录下，沿用 `app.py` 已有的 `/static` 挂载：

```text
static/exercises/
├── data/
│   ├── exercises.json
│   └── exercises.schema.json
├── images/
├── videos/
├── LICENSE
└── NOTICE.md
```

训练详情使用的地址形如：

```text
/static/exercises/videos/0001-2gPfomN.gif
/static/exercises/images/0001-2gPfomN.jpg
```

不复制上游演示页面和开发指南，避免把无关工具带入 XunJi。许可证和 `NOTICE.md` 必须保留在本地资源目录，另外在项目文档中记录来源仓库与媒体版权说明。

## 4. 数据与匹配架构

新增 `exercise_media.py`，职责限制为：

1. 懒加载并缓存本地 `exercises.json`。
2. 以规范化英文动作名建立索引。
3. 将 XunJi 中文动作名转换为明确的数据集名称别名。
4. 返回本地 GIF、缩略图和署名信息。
5. 为训练动作生成可选媒体字段，不修改原始训练数据。

规范化规则只处理确定性差异：大小写、连续空白、连字符、斜杠和训记动作名后缀（例如 `_胸部训练`）。不使用模糊相似度匹配；无法确认时返回 `None`。

匹配优先级：

1. API 保留的原始英文动作名与数据集名称精确匹配。
2. 去除训记后缀后的英文名精确匹配。
3. 明确维护的中文别名匹配常见动作，例如“杠铃卧推”对应 `barbell bench press`。
4. 无匹配结果，不显示媒体。

动作中文化流程需要保留非展示用途的原始动作名，展示仍使用现有中文名称。媒体字段为可选字段，不改变分析模块使用的动作名称。

返回结构示例：

```python
{
    "gif_url": "/static/exercises/videos/0001-2gPfomN.gif",
    "image_url": "/static/exercises/images/0001-2gPfomN.jpg",
    "attribution": "© Gym visual — https://gymvisual.com/",
}
```

## 5. 请求与页面数据流

训练详情片段和训练页首次渲染都在模板渲染前执行相同流程：

1. 从数据服务读取训练记录。
2. 应用现有中文动作名转换。
3. 合并重叠训练记录。
4. 为每个动作调用媒体匹配器并附加可选媒体字段。
5. 将训练数据传入 `training_detail.html`。

这样，日历点击加载的详情和训练页初始显示的今日详情行为一致。缓存、历史回填、训练分析和动作追踪接口不参与媒体加载。

## 6. 页面交互

对已有动作信息块做最小扩展：

- 有匹配媒体时，在动作名称和组数信息旁显示 GIF。
- 使用 `loading="lazy"`，降低详情页初始请求压力。
- 保持 180×180 原始尺寸，不放大媒体文件。
- `alt` 使用当前中文动作名加“动作示意图”。
- 图片旁显示 `© Gym visual — https://gymvisual.com/`。
- GIF 加载失败时尝试对应 JPG；两者都失败则隐藏图片，保留文字详情。
- 无匹配媒体时不渲染空图片容器。

不新增页面级图库控件，不改变训练详情现有布局和移动端结构；CSS 只增加媒体容器、缩略图尺寸和署名样式。

## 7. 错误处理与安全边界

- 数据文件缺失、JSON 无法解析或资源索引异常时，媒体匹配器返回空结果；训练详情继续显示文字内容。
- 单个动作资源缺失不影响其他动作。
- 模板不拼接用户输入作为文件路径；资源路径只来自本地数据集文件并经过目录约束。
- 不把上游资源 URL 作为运行时依赖。
- 所有媒体继续保留上游要求的署名；本地化不改变媒体版权归属。

## 8. 测试与验收

新增媒体模块测试：

- 数据集加载数量为 1,324。
- 代表性记录的 JSON、JPG 和 GIF 路径存在。
- 常见中文动作可命中正确数据集记录。
- 原始英文动作名可命中正确数据集记录。
- 未知动作返回空结果。
- 媒体标注不修改输入训练数据。
- GIF 缺失时能返回 JPG 回退路径。

执行完整 pytest，确保现有训练、分析、缓存和路由测试不回归。验收以以下结果为准：

- 训练详情中常见动作出现本地 GIF。
- 未匹配动作仍正常显示名称与组数。
- 浏览器网络请求只指向 `/static/exercises/...`，不依赖 GitHub。
- 所有 1,324 条数据记录引用的媒体文件均已落盘。
- 规格中的许可证和来源文件存在且署名文本完整。
